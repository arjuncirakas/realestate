You build one React feature area for the Estate Platform. Stay inside your assigned owned paths from Section 13.

## Before you start

Read `docs/PROJECT_REQUIREMENTS.md` Sections 2.4, 5.2, 7, and 9.3. Reuse the existing `components/ui` primitives — do not build your own Button, Input, Card, Skeleton, EmptyState, or ErrorState. Use `lib/format.js` for INR currency and area formatting — do not write another formatter. Import form schemas from `frontend/src/contracts/` (generated by `npm run contracts:sync`); never hand-edit that directory or redefine validation locally.

## Hard rules

- JavaScript ESM only — `.jsx` for components, `.js` for modules. No TypeScript, no `require()`.
- One React Query hook per endpoint in `src/api/`. Components never call axios directly.
- Structured array query keys: `['properties', 'list', filters]`, `['properties', 'detail', slug]`.
- Theme tokens only (`bg-parchment`, `text-ink`, `border-hairline`, `text-moss`, etc.). No inline colour literals.
- No `localStorage` or `sessionStorage` for tokens — access token in memory, refresh in httpOnly cookie.
- Buttons name their outcome ("Register interest", "Request site visit", "Save plot") — never "Submit".
- Shared-file edits only: one `import` + one route entry in `frontend/src/routes/index.jsx`. Nothing else.
- Named exports except page components (default export). JSDoc on exported functions. No `console.log`, no `TODO`, no commented-out code.
- There is no `tailwind.config.js` in Tailwind v4 — do not create one. Tokens live in `@theme` in `index.css`.

## Four states on every list

Every list view must explicitly handle:

1. **Loading** — skeleton placeholders, not a bare spinner
2. **Empty** — instructive copy, e.g. "No saved plots yet. Browse the catalogue to save one."
3. **Error** — what happened and what to do next
4. **Success** — the data

A spinner alone is unacceptable.

## Design discipline (Section 7.2)

The interface should feel like a serious record-keeping system — closer to a land registry than a travel site. Restraint reads as trustworthy. Follow the hairline borders, 6px radius, sentence case, Inter + IBM Plex Mono identity strip, and price/area typography rules from the spec. No marketing-funnel clutter.

## Maps cost rules (Section 7.3) — mandatory

- Listing cards/grids use Static Maps API only — one static image per card, cached by URL.
- Exactly one interactive map instance per page; unmount when hidden.
- Debounce viewport queries at 500ms.
- Cache map results in React Query with 5-minute `staleTime`, keyed on rounded bbox coordinates.
- Never geocode from the browser.

## Group purchase

If you are building group-purchase pages, Section 1.3 compliance is your primary responsibility. Use only approved vocabulary ("register your interest", "indicative amount", "the agency will contact you", "group purchase opportunity", "enquiry"). Ban returns/yield/ROI figures, the words invest/investment/investor/shares/units/portfolio returns/dividend, countdown timers, funding progress bars, "X spots left", and any binding-commitment implication.

## Before reporting done

```
npm run lint
npm test
npm run contracts:check
```

Confirm you touched only owned paths (plus the permitted one-line route registration).

## When to stop and message the lead

Do not guess. Stop and report to the lead when:

- A required contract schema is missing from `frontend/src/contracts/` or looks wrong
- You need a UI primitive or layout change outside your owned paths
- You need to edit another teammate's feature folder
- An API endpoint you depend on is missing or returns an unexpected shape
- Copy for group purchase sits near the Section 1.3 line and you are unsure
